# Cursor Telegram Bridge 0.4.11

- `/model` buttons now come from `cursor-agent models`, the list Cursor itself offers, so a newly released model shows up without a bridge update. The variants of one model (context size, effort, Thinking, Fast) fold into one button. The newest version of each main family comes first: Claude Opus, Claude Fable, Claude Sonnet, GPT, Composer, Grok, and Gemini, then everything else. Auto is left out of the menu; typing `/model auto` still works.
- The list is cached in the state directory as `cursor-bridge-<name>.models-cache.json`. When the cache is older than `CUB_MODEL_MENU_TTL_S` (default 21600 seconds, six hours), one background thread refreshes it and the menu shows the cached list meanwhile, so a tap never waits for the CLI. At startup the bridge also refreshes a missing or old cache. A failed refresh leaves the cache alone and is tried again after five minutes. `CUB_MODEL_MENU` still overrides the list. The built-in list is used only when there is neither a live list nor a cache, and it now includes Claude Opus 5.5 and Claude Fable 5.2.
- Choosing a model is stricter. A version number is matched whole: `/model opus 5` picks Opus 5, never Opus 5.5, and a name that stops in the middle of a version is refused. When the right row is not the highlighted one, the bridge moves down to it one row at a time and checks the highlight after each step. After choosing a row that way, it checks the status line and reports a mismatch instead of success. When it cannot find or reach the row, it clears the input box and chooses nothing.
- Buttons in a menu that is already on your phone keep working after the list is refreshed.
- The ✅ mark now finds the current model when the status line adds context size and effort (`Claude Opus 5.5 300K Extra High`), and in a new session whose status line has no context column yet.
- Telegram polling is sturdier. `getUpdates` now asks Telegram to hold the request for up to 30 seconds and gives the socket 15 seconds more than that. In 0.4.10 the 30-second value only set the socket timeout, so Telegram answered at once and the bridge asked again right away; bridges that ran for days could fail most polls with `URLError`. A failed poll now logs the error type, HTTP code, errno, and reason, with URLs and tokens removed. The wait between failures grows from 1 second up to 60 seconds. After 30 failures in a row, or 10 minutes of failures, the bridge exits with an error so that launchd or `systemd --user` restarts it. The health file gains `last_poll_ok_at` and `poll_fail_streak`.

Validation: the bridge's unit suite (244 tests), including 15 new tests for the model menu (parsing a captured `cursor-agent models` output, folding, ordering, the cache lifetime and background refresh, the `CUB_MODEL_MENU` override, failure fallback, buttons from an older menu, row matching and moving down, and the status line with and without the context column); the 15 menu tests also on Python 3.9; mutation probes on the new menu, matching, and status-line code; a live check against a throwaway Cursor CLI (2026.11.13) on a disposable tmux server, switching to Grok 4.6, Claude Opus 5 (one row down from Opus 5.5), Claude Fable 5.2, and back to Claude Opus 5.5, with the Cursor settings file restored afterwards; the menu change running on four machines, each logging a refreshed list of 43 models; the public export with the internal-symbol audit and the undefined-global gate; private-data and token scans with two independent scanners compared against 0.4.10; manifest parity; release-notes lint; and the public suite (101 tests; 4 other-engine skips and 1 skip for the ACP lane that the public build does not bundle; run on Python 3.14 and 3.9). A source bundle is included; install all shared modules alongside the bridge.

This is a GitHub release. It does not upload to PyPI or restart an installed bridge. The bridge changed, so restart a running bridge to use 0.4.11.
