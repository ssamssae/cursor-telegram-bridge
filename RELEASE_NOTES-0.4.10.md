# Cursor Telegram Bridge 0.4.10

- `python3 bridge_setup.py doctor` checks an install at any time and changes nothing. It prints one line per check, marked `[ok]`, `[warn]`, or `[fail]` with a short reason, ends with `doctor complete: N failure(s), M warning(s)`, and exits with 1 when any check fails. It checks that `bridge.env` exists and only your user can open it, and that the chat id is set and is not the example value. It checks that the token file exists, is private, and holds a token; it never prints the token. It finds `cursor-agent`. It checks tmux, the bridge's tmux session, and the Cursor agent inside it. While tmux or the session is missing, each message runs one headless `cursor-agent`, so the doctor warns; with `CUB_TUI_FALLBACK_HEADLESS=0` it reports a failure instead. It checks the background service: the launchd agent is loaded on macOS, and the `systemd --user` unit is active on Linux.
- The doctor asks Telegram once (`getMe`) whether it accepts the token. A refused token is a failure; no answer at all is only a warning. `--offline` skips that call.
- On Linux the doctor also checks linger. With `Linger=no`, the service stops when you log out, so the doctor warns and prints the command that turns linger on (`sudo loginctl enable-linger <user>`). It does not run that command.
- The doctor repeats setup's warning about a Cursor agent on a terminal outside the bridge's tmux session, because your phone cannot see that window. Use `cursor-tg` instead.
- Setup now ends with `Check the bridge again any time: python3 bridge_setup.py doctor`.
- Setup keeps a copy of a service file that it did not write before it replaces that file. The systemd unit and the launchd plist that setup writes now carry a marker line. When a file with the same name exists without that line, setup saves a timestamped copy next to `bridge.env`, warns, and then replaces the file. An interactive setup asks first; answer `n` and setup leaves that file and the service alone. A unit or plist written by 0.4.9 has no marker yet, so the first setup run after the update keeps one copy of it.
- `setup --dry-run` now lists the files already there that setup would write over, with what happens to each. A saved token file is not on that list: setup reuses it unless you paste a new token.

Validation: unit coverage for the doctor (a healthy install, a missing `bridge.env` with exit code 1, files that other users can open, a refused token and no answer from Telegram, `--offline` with no network call, a missing or example chat id, an empty or missing token file, linger off and on with the command never run, a `systemd --user` service that is inactive, not installed, or unavailable, a launchd agent that is loaded, not loaded, or not installed, tmux and the session missing with and without the headless fallback, a missing `cursor-agent`, Cursor in the bridge session and on another terminal, the parser, and Telegram's refusal body) and for the service-file copy (a foreign unit or plist copied next to `bridge.env` and replaced, a file that setup wrote replaced without a copy, the interactive question answered `n` and yes, and the dry-run list); 57 setup tests, also run on Python 3.9; mutation probes on the linger check, the outside-session warning, the doctor's exit code, and the service-file copy; the doctor run for real in a throwaway home with a disposable tmux server; the public export with the internal-symbol audit and the undefined-global gate; private-data and token scans with two independent scanners compared against 0.4.9; manifest parity; release-notes lint; and the public suite (101 tests, 19 of them new setup tests; 4 other-engine skips and 1 skip for the ACP lane that the public build does not bundle; run on Python 3.14 and 3.9). A source bundle is included; install all shared modules alongside the bridge.

This is a GitHub release. It does not upload to PyPI or restart an installed bridge. The bridge itself did not change, so a running bridge needs no restart.
