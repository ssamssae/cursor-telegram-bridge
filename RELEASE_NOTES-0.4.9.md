# Cursor Telegram Bridge 0.4.9

- One command sets the bridge up: `python3 bridge_setup.py setup`, standard library only. Its first question is `Use the author's setup (recommended)? [Y/n]`, and the default is yes; `setup --like-author` skips the question. Setup reads the bot token at a hidden prompt and checks it with Telegram, learns your chat id from a `/start` you send in a private chat (group chats are refused), writes `~/.config/cursor-telegram-bridge/bridge.env` readable by you only (an existing file is kept as a timestamped backup), starts Cursor inside the tmux session `cursor` (a running session is left as it is), registers a background service (launchd on macOS, `systemd --user` on Linux), links the `cursor-tg` command into `~/.local/bin`, and sends one test message. `--dry-run` prints the plan without touching files, services, or Telegram.
- The author's setup differs from the public defaults in three settings: `CUB_TUI_MIRROR_LOCAL=1` (turns typed in the Cursor window also reach your phone), `CUB_FLOW_MIRROR=1` (the progress card with its Stop button), and `CUB_CONTEXT_CLEAR_PCT=0` (no automatic `/clear`). Answer `n` and the public defaults stay as they were; tmux is then optional, and without it each message runs one headless `cursor-agent`.
- The author's setup ends with a self-check: bot to phone, phone to terminal and back (60 s), and terminal to phone (90 s). The three result lines appear in the terminal and in Telegram, and a step that times out says why in one line. The self-check never types into the Cursor window while Cursor is showing a question, such as workspace trust, a tool approval, a letter menu, or the model picker. On a new folder the trust question defaults to Trust, so the self-check reports that step as skipped instead of answering for you.
- `cursor-tg` attaches any terminal to the one Cursor session the bridge drives, using the tmux socket and session from `bridge.env`. If the session is missing, it starts Cursor there first. It never detaches a terminal that is already attached, and inside the same tmux server it switches to the session instead of nesting.
- Setup warns when a Cursor agent runs on a terminal outside the bridge's tmux session, because your phone cannot see that window.
- With the flow mirror on, a turn you type in the Cursor window gets the same progress card with a Stop button as a turn sent from your phone. A phone turn keeps precedence: while it runs, the terminal card is handed over and its button is refused. A press after the terminal turn has ended is refused as an ended request.
- If you already start the bridge by hand, stop that copy before you run setup. Two bridges polling one bot conflict.
- The setup regression test `tests/test_bridge_setup.py` ships with the public suite.

Validation: public export with the internal-symbol audit and the undefined-global gate (no undefined names in any of the six modules), private-data and token scans with two independent scanners (no new private values against 0.4.8), manifest parity, release-notes lint, and 82 tests (38 new setup tests; 4 other-engine skips, 1 skip for the ACP lane that the public build does not bundle) on Python 3.14. A source bundle is included; install all shared modules alongside the bridge.

This is a GitHub release. It does not upload to PyPI or restart an installed bridge.
